On-Chain Architecture

GenomeRegistry Contract

Calls IWorldID.verifyProof(root, 1, signal, nullifierHash, externalNullifierHash, proof[8]) before any state write (CEI pattern). Maps nullifier_hash → CID. Reverts with AlreadySubmitted on duplicate. Mints 500 GNM via MINTER_ROLE.

RecordVault Contract

Patient pushes encrypted file to IPFS → CID → Record{cid, recordType, uploadedAt} appended to per-patient array. Patient key never leaves device. Mints 10 GNM per record. getRecordCount(address) for dashboard.

ConsentManager Contract

ConsentGrant{active, expiry uint64, dataTypes bytes32, grantedAt}. Patient signs: institution, data types, study scope, expiry. Revocable in one tx. Timestamped audit trail. 21 CFR Part 11 compatible. 5

PBH — Priority Blockspace for Humans 3

Orb-verified humans get sequencer priority + gas subsidies. Mainnet live June 26, 2025. Patient uploads never get frontrun by MEV bots. High-frequency medical record updates don't require users to hold ETH — gas sponsorable via paymaster.

StudyRegistry Contract

Pharma/research institutions publish studies on-chain: eligibility criteria, data types required, budget per patient. Patients browse and consent. All study terms are immutable once posted — no retroactive scope creep. Part of the two-layer research marketplace.

LabRegistry + LabAttestation Contracts

LabRegistry whitelists approved sequencing labs. LabAttestation records lab signatures: attest(patient, genomeCID, labId, sig). GenomeRegistry requires a valid lab attestation before accepting any genome — prevents fabricated data from corrupting research cohorts.

WorldChain Anon RPC

All patient transactions broadcast via WorldChain's anonymous RPC. Strips IP address from tx submission — no IP→wallet→medical data linkage. A patient uploading their genome cannot be identified by network-level surveillance regardless of jurisdiction.

What Arkiv Stores

Medical record metadata — not the files themselves. The encrypted files live on Lighthouse/IPFS. Arkiv stores the index that makes them discoverable and queryable by consented institutions.

Entity: medical_record_v1

type (genome/lab_report/prescription/imaging/bill) · cid (IPFS CID of encrypted file) · date · institution · icd10Category · tags[] · anonymousId (partial nullifier for cross-referencing)

What Makes It Different From Postgres

The row owner is the patient's wallet — not a DBA. Consent is enforced by on-chain ConsentManager state at query time. 10-year expiry is structural, not a cron job. No central database to breach — CIDs are meaningless without the patient's AES key.

What Institutions Can Query

With a valid on-chain ConsentGrant: "patients where icd10Category = 'metabolic' AND tags CONTAINS 'HbA1c' AND type includes genome." Finds matching cohorts without accessing any file content. Files accessed only after TEE compute step.

GDPR Compliance Properties

Art. 17 (erasure): patient destroys AES key → file irrecoverable. Art. 5(1)(e) (storage limitation): entity expires at 10 years structurally. Art. 7(3) (withdraw consent): one tx to ConsentManager, Arkiv stops serving immediately on next query.

Fix 1: Protocol Pre-Registration Hash

Replaces: "Replace ClinicalTrials.gov registration ✗ Not feasible"

Problem being solved: Outcome switching — researchers register a trial, see interim results, then change the primary endpoint before publication. A 2015 NEJM study found ~50% of trials show discrepancies between registered and published primary outcomes. 14 FDAAA 2007 §801 mandated CT.gov registration but cannot prevent protocol amendment after registration.

  • What GenomeChain does: Before submitting to ClinicalTrials.gov, the institution calls registerProtocol(keccak256(protocolJSON)) on WorldChain. This timestamp is immutable.
  • When CT.gov registration is submitted, the NCT number is linked to the on-chain hash. Any subsequent protocol amendment creates a new hash — the original is preserved.
  • Peer reviewers and journal editors can verify: "Protocol as submitted to CT.gov matches the hash registered on WorldChain before trial start." Outcome switching becomes cryptographically detectable.
  • CT.gov registration still required — FDAAA §801 is satisfied via CT.gov. The blockchain hash is an additional integrity layer, not a substitute registry.
  • This is a novel contribution — no current trial registration system provides immutable pre-registration timestamps at this granularity.

Fix 2: ConsentManager as IRB Execution Layer

Replaces: "Replace IRB consent process ✗ Not feasible"

What IRB does (unchanged): An Institutional Review Board reviews and approves the study protocol and the consent form text before recruitment begins. This is a legal requirement under 21 CFR Part 56 and applies globally. IRB approval cannot be replaced by any technology. It doesn't change.

What ConsentManager adds (the fix):

  • Execution: IRB approves the consent form. ConsentManager executes that form at the individual patient level. Each patient's consent tx encodes: institution, approved data types, study scope, duration, IRB protocol ID.
  • Granularity: Paper consent is binary (yes/no). ConsentManager encodes bytes32 dataTypes — patients consent to specific data types (genome, records, genomic markers) separately. IRB-approved granularity, digitally enforced.
  • Auditability: Regulators can verify: "Patient consented at [timestamp], under IRB protocol [hash], to [data types], expiring [date]." Paper forms are archived in binders. This is on-chain and queryable.
  • Revocation: FDA's eConsent guidance (2016) explicitly endorses the ability to withdraw consent at any time. 16 revokeConsent(institution) executes this instantly and verifiably.
  • 21 CFR Part 50.27: Documentation of informed consent. ConsentManager's on-chain timestamped tx is a superior documentation record vs. paper signature stored in a site binder.
  • GDPR Art. 7: Freely given, specific, informed, unambiguous. ConsentManager's typed data types satisfy "specific." Revocability satisfies "freely given." Timestamp satisfies documentation requirements.

Study Metadata

Study type, population criteria (genome-matched), data sources, institution identifier, approval authority (FDA/EMA). Stored as structured on-chain data, queryable by patient profiles automatically.

Finding Tags

Machine-readable: gene variants studied, drug names, disease codes (ICD-10), ancestry groups affected. Smart contract routes findings to matching patient profiles — no manual notification required.

Pre-Registration Verification

At publication, smart contract verifies: results hash links back to protocol hash registered before trial start. If endpoints changed without a registered amendment, the mismatch is publicly detectable. Outcome switching becomes auditable.
